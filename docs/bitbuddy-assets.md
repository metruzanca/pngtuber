# BitBuddy assets → pngtuber skin

BitBuddy (Steam, by Saltfish) ships its artwork in a single Godot 4.6 data
pack, `BitBuddy.pck`. The artwork is **copyrighted** — pngtuber never ships or
commits it. This page explains how to install a skin you own into pngtuber's
user data directory using the committed tooling. You may of course supply your
own rig parts instead (any PNGs + a `manifest.toml`).

## The pipeline

```
BitBuddy.pck ──godotpcktool──▶ extracted res:// tree
   └── .godot/exported/<hash>-coworker_1036.scn   (binary rig scene)
   └── assets/skins/alien_cat/*.png.import        (texture provenance)
                    │
        headless godot + tools/dump_scene.gd
                    ▼
         Sprite2D nodes JSON (name, position, z_index, texture)
                    │
   tools/scene2manifest (Go)
                    ▼
   manifest.toml (parts + scene-derived offsets + variants/animations)
```

Everything below was verified against a real BitBuddy 4.6.1 pack (41 MB,
6333 files).

## 1. Extract the pck

Requires `godotpcktool` (NixOS: `nix-shell -p godotpcktool`):

```sh
./tools/extract_pck.sh "$HOME/.local/share/Steam/steamapps/common/Bit Buddy/BitBuddy.pck" /tmp/pckout
```

This unpacks the whole pack preserving `res://` paths, including the binary
`coworker_*.scn` rig scenes, the `.godot/imported/*.ctex` textures and the
`.remap`/`.import` metadata Godot needs to resolve dependencies.

## 2. Dump the rig scene

The coworker rig scenes are **binary** PackedScenes (`RSRC` magic), not text
`.tscn`, so we load them with headless Godot:

```sh
nix-shell -p godot --run \
  'godot --headless --path /tmp/pckout --script tools/dump_scene.gd -- \
     res://.godot/exported/133200997/<hash>-coworker_1036.scn' > nodes.json
```

Find the right `<hash>` for alien_cat with:
`godotpcktool -p BitBuddy.pck -a list -i coworker | grep coworker_1036`.

The dump is an array of `Sprite2D` nodes (`name`, `position`, `scale`,
`z_index`, `texture`, `texture_size`). The desk/keyboard/mouse sprites are the
coworker's environment and are ignored by the generator.

## 3. Generate the manifest

```sh
go run ./tools/scene2manifest -dump nodes.json -skin alien_cat -out manifest.toml
```

This maps the coworker node naming (`LeftHandUp/Down` → `left` variants,
`Mouth1..3` → `mouth` frames, …), converts Sprite2D **centers** to top-left
offsets, normalizes the rig to the origin, orders parts by `z_index`, and
emits `[character.parts]`, `[character.offsets]`, `[character.variants]` and
`[character.animations]` (blink + mouth talk).

## 4. Copy the skin into pngtuber's data dir

```sh
SKIN="$HOME/.local/share/pngtuber/assets/skins/alien_cat"
mkdir -p "$SKIN"
cp /home/…/assets/skins/alien_cat/*.png "$SKIN/"
cp manifest.toml "$SKIN/manifest.toml"
```

## 5. Run

```sh
pngtuber --skin alien_cat            # or: PNGTUBER_SKIN=alien_cat pngtuber
```

The window auto-sizes to the rig's bounding box (alien_cat → 154×149) and the
composite is built from the scene-derived offsets, so it renders correctly in
OBS Game Capture ("Allow Transparency") / PipeWire without hand-tuning.

## Asset layout reference

```
~/.local/share/pngtuber/assets/
└── skins/
    └── <skin>/
        ├── manifest.toml      # generated by scene2manifest
        └── <part>_*.png       # rig parts (copyrighted, user-owned)
```

Resolution order: `PNGTUBER_ASSETS` env → `--assets` flag →
`$XDG_DATA_HOME/pngtuber/assets`; within it `<assets>/skins/<skin>/manifest.toml`
(if `--skin`/`PNGTUBER_SKIN`) else `<assets>/manifest.toml`. If nothing is
found the committed placeholder is used and the choice is logged.
